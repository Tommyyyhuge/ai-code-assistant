诊断结果：前端"修复时卡退"根因分析

共发现 10 个问题，3 个直接导致卡退

🔴 直接导致"修复时卡退"的根因

① HMR 错误覆盖层被关闭

vite.config.ts:9 — hmr: { overlay: false }

核心根因！修改代码后 HMR 产生错误，但覆盖层被禁用，错误不可见，React 树崩溃 → 白屏/"卡退"

修复：改为 overlay: true 或删除 hmr 配置块

② TypeScript 6.0.2 pre-release 不稳定

package.json + tsconfig.app.json

TS 6 尚未正式发布，erasableSyntaxOnly 实验特性在 HMR 时可能产生意外编译行为

修复：降级到 TypeScript 5.8 稳定版

③ 零错误边界 → 小错导致整体崩溃

整个项目无 ErrorBoundary 组件

任何组件中未捕获的错误都会卸载整个 React 树，HMR 重载时极易触发

修复：添加 ErrorBoundary + 全局错误处理

🟠 运行时会崩溃的问题

④ API 响应格式不匹配

authStore.ts:34,41,78 — response.data.data 访问不存在的嵌套属性

FastAPI 返回平铺 JSON，前端却多解包一层 → 所有登录/注册必定抛 TypeError

⑤ 缺少 Tailwind CSS 依赖

package.json 无 tailwindcss，无配置文件，但所有组件使用 Tailwind 类名

不影响崩溃，但样式完全失效

⑥ CSS 嵌套无 PostCSS 插件

App.css 使用 SCSS 嵌套语法，无 postcss-nesting 插件

可能产生隐藏编译警告/错误

🟡 次优先级问题

⑦ 401 拦截器用 window.location 硬跳转

api.ts:28 — 应使用 React Router navigate()

⑧ register → login 链式调用竞态风险

authStore.ts:55 — 状态更新不原子
